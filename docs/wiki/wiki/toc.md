## Recently updated
- [A spool between the mailbox and the Amp thread](architecture/architecture-spool-and-wake.md) — amp-email-listener is a single-file Amp plugin that polls configured mailboxes while Amp runs, writes raw .eml files plus an append-only index under the Amp config directory, and appends a pointer to each new message to a thread, which wakes the agent. There is no separate service: the provider cursor in the spool is what catches up mail that arrived while Amp was off. Providers plug in through two calls, and the sync cursor belongs to the provider. (2026-11-17)
- [An inbox the package can create itself: AgentMail's agent sign-up](architecture/agentmail-agent-inbox.md) — AgentMail lets a program create an agent inbox with one unauthenticated POST — no human sign-up, card, domain, app password or OAuth — and the inbox is readable over IMAP with its API key as the password, so the existing imap source reads it unchanged (proven live 2026-10-09 with suruiling@agentmail.to; the original live sign-up). Email: Set up a mailbox (email.setup) offers it first: a name, and the agent has an address, with its Spam folder watched too. After setup it offers to open the claim page; claiming makes the key recoverable and unlocks sending. Without a human attached the inbox can receive but cannot send to anyone, which matches the no-send boundary. The price: a lost key cannot be recovered, a third party holds the mail, and inbound mail that fails authentication is dropped without a bounce. Arrival of a real message is still to be proven. (2026-11-17)
- [No gate, a pointer not a digest, and watching while Amp runs](decisions/decision-no-gate-and-pointer.md) — amp-email-listener turns the agent for every message — no relevance gate, no batching, no suppression rules — and the wake carries the sender, the subject and a file path rather than the body. The plugin starts watching when it loads with a configured mailbox; Email: Start Watching Mail binds delivery to a thread, Email: Stop Watching Mail stops polling, and Email: Choose Delivery Target selects this thread or a new thread per email. A message with a link or attachment turns the agent with shell, edit and write blocked until the turn ends. (2026-11-17)
- [A mail turn meets wiki capture](gotchas/gotcha-mail-turn-meets-capture.md) — A message delivered by a wake is read by the agent, so its text is in the transcript — and wiki capture snapshots the transcript. A session watching mail therefore feeds third-party mail into whichever wiki captures that session, including this one, unless capture is off for it. The Amp plugin does not warn when watching starts; check capture before Start Watching Mail. (2026-11-17)
- [Installed from npm, the background fetcher could not start (fixed 2026-10-09)](gotchas/gotcha-npm-install-cannot-start-fetcher.md) — Historical (pi-era). An npm-installed copy loaded the extension but could not start the detached fetcher, for three independent reasons: scripts/ was not published, Node refuses to strip types under node_modules, and plain node cannot resolve the pi peer that config.ts and spool.ts imported at top level. It only ever worked on Andrei's machine because pi loads this checkout. Fixed the way pi-jev-wiki does it: src/daemon.mjs loads the fetcher through jiti, nothing but the extension imports pi, and the extension hands pi's agent directory to the rest. Proven from a real npm-style install with no pi peer, and guarded by self-check. The project is now a single-file Amp plugin; this page records the pi-era packaging bug. (2026-11-17)
